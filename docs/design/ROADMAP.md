# Roadmap

## M0: Governance And Translation Plan

Establish project authorities, source/research boundary, M/T/S/P lifecycle, M0 plan, validation contract, and portable-C constraints. Exit when the project can admit ROM research without ambiguity about provenance or proof.

## M1: Reviewed Source Corpus And Local Toolchain

Admit one ROM revision and reviewed disassembly under local-only policy. Build address maps, code/data ownership, and bounded extraction/probe tools.

## M2: Reference Execution And Validation Protocol

Create owner-local reference execution, deterministic input recordings, neutral state checkpoints, and trace comparison rules. This is validation only.

## M3: Portable C Program Foundation

Translate startup, RAM model, frame/NMI structure, controller flow, and neutral command contracts into C90 with unit-level equivalence evidence.

## M4: Complete Logic Translation

Translate all admitted game routines, tables, area data, object systems, and audio commands; achieve complete provenance coverage and route-level traces.

## M5: Native Windows Presentations

Deliver Windows graphical and 80×25 colored-object renderers over the same translated game state.

## M6 And Later: 16-Bit Native Delivery

Bring the portable game layer to a 16-bit C toolchain and DOS VGA full-screen adapter, then verify its supported logic routes against the established oracle.
